# DocWen Assistant — 交互规范

[English synced translation](ux-spec.en.md)

## 入口

用户可从侧边栏图标、文件资源管理器的 **DocWen** 子菜单和命令面板启动操作。菜单项必须根据当前文件检查与 Machine capability 显示，不能仅凭扩展名推测支持情况。

## 导出流程

导出先检查源文件和可用能力，再让用户选择目标格式、模板或受支持的优化项。用户必须通过原生保存对话框明确目标；格式与扩展名冲突或已有目标需要明确确认，相关资源不得覆盖既有文件。

## 编号与校对

标题编号对隔离副本运行，提交前再次验证按路径唯一匹配的 Markdown leaf、view、编辑器与源快照；出现多个匹配 view 时失败关闭。校对结果显示在侧栏，不直接改写笔记；问题项是可键盘操作的控件，关闭视图只取消该视图观察的校对任务。

## 状态与恢复

长操作显示运行或取消状态。设置保存失败必须保留用户已修改的模型并提供重试；Machine、自动别名、手动路径、冲突或协议错误必须给出稳定的用户摘要与可脱敏技术详情，不能把失败显示成成功空结果。

## 设置界面

五个顶部页签分别是常规、转为 Markdown、转为 Word、校对和使用方法。常规页默认自动发现 Microsoft Store 安装版、显示经过验证的连接状态，并只在手动便携版模式下显示路径控件。Obsidian 1.13 界面从同一个共享页面模型渲染这些页签。构建顶部页签本身不得访问文件系统或启动进程；常规页状态行渲染后可以发起一次静默且有界的连接检查。

## 本地化

界面、通知和资源查询使用同一解析后的语言。默认跟随 Obsidian，用户可以明确选择支持的语言。语言改变不能更改底层 capability、路径或写入语义。

## 可访问性与布局

页签列表必须提供完整的 tab、tabpanel、选中状态与 roving tabindex 语义；左/右键适配 RTL，上/下键切换页签，Home/End 跳到两端，并让当前页签滚入可见区域。活动页签同时使用强调色下划线和半粗字重，页签基线与内容面板之间保留稳定间距。页签需适配 20 px 界面字号、窄宽度、第三方主题和粗指针的 44 px 点击区。页签本身就是页面标题，内容面板不得重复同名标题。取消、重试和问题项仍须支持键盘，并保持原生 Obsidian 控件与主题变量。

## 安全反馈

界面必须在写入前让用户看见目标，并在来源或目标发生变化时拒绝提交。日志、错误和公开支持材料不得包含私密正文、Vault 路径、CLI 路径或凭据。
